Qué información se conserva

El modelo conserva la identidad de los estudiantes y el contexto de su intercomunicación: conversaciones, participantes, mensajes y materiales. Separa esos datos de las sesiones temporales y de los permisos de recuperación.

Relaciones del intercambio

Un usuario puede participar en varias conversaciones. Cada mensaje tiene un chat y un autor; una respuesta referencia otro mensaje. El servidor exige que la respuesta y los adjuntos pertenezcan al mismo chat. Las fotos de usuarios y conversaciones también referencian archivos; su conversacion_id puede ser nulo.

Relaciones de acceso y recuperación

contactos_privados tiene dos claves foráneas a usuarios: una para el propietario y otra para el compañero. Las tablas de recuperación pueden tener usuario nulo; no debe interpretarse una solicitud por sí sola como una cuenta acreditada. correo_desafios puede enlazar una solicitud de recuperación.

Integridad e índices

  • UNIQUE(emisor_id, id_envio) impide dos registros para el mismo intento; pareja evita duplicar un chat privado. La API construye la pareja con los identificadores ordenados.
  • PRIMARY KEY(conversacion_id, usuario_id) evita pertenencias duplicadas. La administración del grupo bloquea la conversación para coordinar cambios simultáneos.
  • El índice de mensajes por conversación e ID sirve al historial; el de conversación y actualización sirve a los cambios. Miembros se indexa por usuario y conversación.
  • Los desafíos se indexan por cuenta, correo y hash de sesión para comprobar cuotas y vencimientos. Las sesiones se indexan por vencimiento y por la identidad del JSON.

Conservación y privacidad

Cerrar una sesión no borra el historial. Eliminar un mensaje vacía su texto y activa la marca de eliminación; no equivale a un borrado físico de todos los archivos. Las subidas almacenadas siguen contando para la cuota. Quitar a un miembro corta su acceso; si se le añade de nuevo, podrá consultar el historial de ese grupo.

La contraseña se representa mediante un hash Argon2id; los códigos y permisos tienen vencimiento y consumo. Correos, hashes, códigos, secretos de push y nombres privados no forman parte del perfil público de un compañero.
