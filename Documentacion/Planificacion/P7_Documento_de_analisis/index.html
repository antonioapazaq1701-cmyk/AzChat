El recorrido de un mensaje

Qué ocurre desde que se escribe un mensaje hasta que se recibe.

Recorrido de un envío

  1. La interfaz prepara el texto y los adjuntos, junto con un identificador de envío.
  2. El servidor comprueba la sesión, la pertenencia al chat y el contenido.
  3. La base registra el mensaje y sus relaciones con los archivos.
  4. El servidor devuelve la confirmación; la interfaz distingue un envío guardado de uno pendiente o fallido.
  5. Las otras sesiones consultan las novedades y actualizan el historial sin recargar la página.

Cuando se interrumpe la conexión

La página conserva el pendiente durante la sesión de página. La persona puede pulsar Reintentar; se reutiliza el identificador para evitar duplicar un envío que sí alcanzó a guardarse. Recargar la página puede perder los pendientes y borradores locales.

Leer y avisar son procesos distintos

La consulta del historial no basta para marcar un mensaje como leído: también debe estar visible el chat y alcanzarse el final. Las notificaciones push sirven como aviso y no sustituyen la recuperación del historial.
