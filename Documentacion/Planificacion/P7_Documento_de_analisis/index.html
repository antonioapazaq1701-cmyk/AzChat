P7. Documento de análisis

Funcionamiento lógico, recorrido de los mensajes y respuesta ante errores.

Metodología Ágil · Enfoque incremental e iterativo

Propósito del análisis

Este documento explica cómo funcionan juntos los casos de uso de AzChat. Describe el recorrido de los datos y las respuestas ante errores, manteniendo el alcance de una web de mensajes privados entre dos estudiantes.

El análisis utiliza los conceptos Estudiante, ConversacionPrivada, Mensaje y GestorChat de P6. Los componentes que los implementarán se detallan en P8 y su ubicación en la nube se explica en P9.

Funcionamiento principal

Recorrido de uso de AzChat
EtapaFuncionamiento
Registro y accesoEl estudiante completa los cuatro datos de registro. El servicio valida el código de 6 dígitos, el usuario de 3 a 20 caracteres y la contraseña de al menos 8 caracteres. Comprueba que los identificadores sean únicos y conserva la contraseña protegida. Para ingresar, verifica el usuario o código y la contraseña antes de abrir una sesión de hasta 8 horas. La actividad no renueva ese plazo.
Inicio de una conversaciónCon la sesión vigente, el estudiante busca el nombre de usuario exacto del destinatario, sin distinguir mayúsculas. El sistema abre la conversación existente de esa pareja o crea una si todavía no existe. Ambos participantes deben ser personas distintas. Después se consulta el historial propio.
Envío de un mensajeLa web asigna un identificador al intento y envía el texto y la conversación. El servicio obtiene el emisor de la sesión; comprueba que participe en el chat y valida el límite de 1000 caracteres. Guarda el mensaje antes de confirmarlo. Si ya recibió ese mismo intento, devuelve el mensaje guardado sin crear un duplicado.
Recepción y consultaEl servicio actualiza a los participantes conectados después de conservar el mensaje. Cada navegador muestra el usuario del emisor y evita repetir mensajes con el mismo identificador. Al volver a entrar o recuperar la conexión se consulta el historial para obtener lo que no se recibió en directo.
Cierre de sesiónEl servicio termina el acceso de esa sesión y sus conexiones de actualización. Los mensajes y la conversación permanecen guardados. Un nuevo acceso requiere verificar las credenciales otra vez.

Situaciones alternativas

Respuestas ante errores y desconexiones
SituaciónRespuesta del sistema
Datos o credenciales incorrectosEl registro no se completa si faltan datos, el formato es inválido o un identificador ya existe. Un ingreso incorrecto no crea una sesión. La interfaz muestra un aviso breve y permite corregir los campos.
Destinatario inexistenteUna búsqueda sin coincidencia exacta no abre una conversación con otra persona ni expone una lista de cuentas. Se informa que no se encontró el usuario.
Texto inválidoSe rechazan un mensaje vacío, uno formado solo por espacios y un texto superior a 1000 caracteres. No se guarda ni se distribuye el mensaje rechazado.
Envío fallido o sin confirmaciónSe conserva el texto en la página abierta y se informa el fallo. El estudiante decide cuándo pulsar Reintentar. Se mantiene el identificador del mismo intento; si el servicio ya lo guardó, no se duplica. Un contenido distinto constituye otro intento.
Conexión perdidaSe informa la desconexión. La recuperación del canal permite volver a recibir actualizaciones y consultar el historial; no reenvía automáticamente los textos pendientes.
Sesión vencida o conversación ajenaUna sesión vencida exige ingresar de nuevo. Si la cuenta no pertenece a la conversación, el servicio rechaza tanto la consulta como el envío y las actualizaciones en directo.

Reglas que se mantienen durante todo el flujo

  • Una conversación tiene exactamente dos participantes distintos y una pareja comparte un único chat.
  • El emisor se obtiene del acceso verificado; no se acepta que el navegador elija otra identidad.
  • Consultar, enviar y recibir mensajes requiere pertenecer a la conversación y mantener una sesión vigente.
  • El historial se conserva y se muestra con un orden estable. Se permite consultar mensajes anteriores sin cargar todo el historial a la vez.
  • Las búsquedas y los mensajes muestran el nombre de usuario. Los códigos, nombres completos y credenciales no se exponen a otras cuentas.
  • Un mensaje guardado se reconoce por su identidad, incluso si su confirmación o actualización se perdió.
