CU-00 Caso de uso general de AzChat

Objetivo: intercomunicarse con otros estudiantes y conservar los intercambios de una coordinación académica en una cuenta personal.

Actor principal: estudiante. Actores de apoyo: otros participantes, administrador del grupo y responsable de recuperación. Gmail API es el servicio externo de correo.

ElementoDescripción
PrecondiciónDisponer de un navegador y conexión. Para acceder a conversaciones se requiere una cuenta y una sesión válida.
InicioEl estudiante desea comunicarse con un compañero o equipo.
Flujo principal1. Crear la cuenta o ingresar. 2. Buscar a un compañero o elegir un grupo. 3. Intercambiar texto, imágenes, archivos o notas de voz. 4. Consultar el historial y las respuestas. 5. Ajustar perfil o preferencias si lo necesita. 6. Cerrar la sesión al terminar.
AlternativasSi olvidó la contraseña, iniciar recuperación. Si falla un envío, revisar la conexión y reintentar. Si no pertenece a una conversación, el sistema deniega su acceso. Crear grupos, exportar chats y activar avisos son opciones según la necesidad.
ResultadoEl intercambio queda disponible para sus participantes autorizados. El estudiante puede volver a consultarlo al ingresar nuevamente.
Relación con el detalleCU-01 a CU-13 desarrollan los recorridos específicos. CU-00 sirve como mapa de lectura y no añade un requisito independiente ni obliga a ejecutar todas las funciones en cada sesión.

Comunicación entre estudiantes

Estos recorridos concretan cómo un estudiante de la universidad puede contactar a sus compañeros, participar en grupos e intercambiar avances. Cada caso explica un objetivo y sus alternativas; los detalles internos están en P7.

CU-01 · Registrarse

Participantes: Persona visitante, Sistema.

Si los datos son inválidos o están duplicados, explicar el error y permitir corregirlos. El correo opcional deberá verificarse antes de vincularlo.

CU-02 · Iniciar sesión

Participantes: Persona registrada, Sistema.

Si las credenciales no coinciden, informar el rechazo sin abrir una sesión.

CU-03 · Iniciar chat privado

Participantes: Persona registrada, Sistema.

Si no hay coincidencias, permitir otra búsqueda. No crear una conversación consigo mismo.

CU-04 · Consultar conversaciones

Participantes: Persona registrada, Sistema.

Si no tiene conversaciones, ofrecer iniciar una. No mostrar chats de otras cuentas.

CU-05 · Enviar mensaje

Participantes: Persona emisora, Sistema, Persona destinataria.

Si falla el envío, conservar el pendiente durante la sesión de página. Reintentar con el mismo identificador para evitar duplicados.

CU-06 · Recibir mensajes

Participantes: Persona destinataria, Sistema, Persona emisora.

Si la persona está desconectada, deberá poder recuperar los mensajes al volver. Un aviso no equivale a lectura.

CU-07 · Consultar historial

Participantes: Persona registrada, Sistema.

Sin pertenencia no se entregará el historial. Si no hay resultados, mostrar un estado vacío comprensible.

CU-08 · Cerrar sesión

Participantes: Persona registrada, Sistema.

Las conversaciones y mensajes deberán conservarse. Una sesión vencida también requerirá un nuevo ingreso.

CU-09 · Recuperar contraseña con correo vinculado

Participantes: Persona solicitante, Sistema, Servicio de correo.

Un código incorrecto, vencido o consumido no habilitará el cambio. No se requerirá autorización administrativa para el correo ya vinculado.

CU-10 · Recuperar contraseña sin correo vinculado

Participantes: Persona solicitante, Sistema, Responsable, Servicio de correo.

Rechazar o dejar vencer la solicitud impedirá continuar. Sin código válido o sin acceso al correo no se completará el cambio. Aprobar no cambiará por sí solo la contraseña.

CU-11 · Compartir una entrega

Participantes: Persona emisora, Sistema, Participante del chat.

Cancelar la previsualización no deberá enviar contenido. Rechazar archivos fuera del tamaño o cantidad permitidos.

CU-12 · Administrar un grupo

Participantes: Administrador del grupo, Sistema, Participante.

No aceptar cambios de una persona sin permiso. Antes de salir, deberá quedar otro administrador si permanecen participantes.

CU-13 · Asignar un nombre privado

Participantes: Persona propietaria, Sistema.

Dejar el campo vacío restaurará el nombre del perfil. No modificar el perfil original ni la vista de otras personas.
