Cómo se conectan sus partes

La relación entre el navegador, el servidor y la base de datos.

Componentes y conexión

ComponenteTecnología y papel
NavegadorHTML, CSS y JavaScript sin React. Presenta las pantallas y consulta la API.
Servidor en RenderNode.js y Express. Aplica reglas y permisos; es el intermediario con los datos.
Base en SupabasePostgreSQL, esquema independiente azchat_complete. Guarda la información de Complete.
CorreoResend mediante HTTPS, invocado únicamente desde el servidor.
Publicación del planGitHub Pages sirve estas páginas estáticas; no ejecuta el backend del chat.

Sincronización real de Complete

El cliente consulta novedades aproximadamente cada 1,8 segundos después de terminar la petición anterior, o cada 6 segundos si la pestaña está oculta. Esta implementación usa consultas HTTP periódicas; no utiliza Socket.IO para distribuir los mensajes.

Protección y operación

El navegador no recibe la conexión de PostgreSQL ni las claves privadas del correo. El servidor usa sesiones y un rol limitado al esquema de Complete; las tablas tienen RLS y no se exponen a los roles públicos de Supabase. La instancia gratuita de Render puede necesitar un arranque tras inactividad, por lo que la espera inicial debe separarse de las mediciones con el servicio activo.
